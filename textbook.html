생활 데이터 웹앱 만들기

GitHub Pages에 올라간 완성본을 먼저 체험하고, 조금씩 내 학교와 내 정류소에 맞게 바꾸는 실습 교재입니다. 목표는 코드를 외우는 것이 아니라 화면을 관찰하고, 설정 파일을 바꾸고, API 응답을 확인하고, AI에게 작은 단위로 질문하며 결과를 직접 검증하는 것입니다.

완성본 주소: https://greatsong.github.io/sample_app/

전체 상세 원문은 docs/TEXTBOOK.md에도 함께 배포되어 있습니다. 이 HTML 페이지는 브라우저에서 본문이 바로 보이도록 JS 렌더링 없이 정적으로 구성했습니다.

전체 결과물

  • 서울 현재 날씨 카드
  • 오늘과 내일 급식 카드
  • 급식 메뉴 투표와 Google Sheets 저장
  • 마을버스 도착 정보 카드
  • 내 학교와 내 정류소로 바꾼 설정
  • GitHub Pages 공개 주소

0장. 완성본 체험하기

이번 목표

완성본을 열어 어떤 데이터가 어디에 표시되는지 관찰합니다. 아직 코드를 고치지 않습니다.

따라하기

  1. 샘플 앱 주소를 엽니다.
  2. 날씨, 버스, 급식 카드가 모두 보이는지 확인합니다.
  3. 급식 메뉴 중 하나에 투표합니다.
  4. 새로고침한 뒤 투표 수가 유지되는지 확인합니다.
  5. 화면 아래의 마을버스 프록시 설정 값을 살펴봅니다.

관찰 기록

내가 본 데이터 1:
내가 본 데이터 2:
내가 본 데이터 3:
신기했던 점:
궁금한 점:
내 프로젝트에서 바꾸고 싶은 점:

확인 체크리스트

  • 샘플 앱 주소를 열 수 있습니다.
  • 날씨 카드가 보입니다.
  • 급식 카드가 오늘과 내일로 나뉘어 보입니다.
  • 투표 버튼을 누르면 숫자가 바뀝니다.
  • 버스 카드가 실시간 연결 또는 설정 필요 상태로 표시됩니다.

AI에게 물어볼 프롬프트

나는 생활 데이터 웹앱 완성본을 관찰하고 있어.
날씨, 급식, 버스, 투표 기능이 각각 어떤 데이터를 보여주는지
초보자 눈높이로 한 문장씩 설명해줘.

1장. 파일 구조 이해하기

이번 목표

앱을 구성하는 파일의 역할을 구분합니다. 초보자는 코드를 모두 읽기보다 먼저 어느 파일을 왜 여는지 알아야 합니다.

파일 역할

index.html: 화면의 큰 구조입니다.
css/style.css: 색상, 카드 모양, 간격, 모바일 배치를 담당합니다.
js/config.js: 학교, 정류소, 프록시 URL 같은 설정값을 모아 둔 설정판입니다.
js/adapters/api-services.js: 날씨, 급식, 버스 API를 호출합니다.
js/adapters/vote-store.js: 급식 투표를 Apps Script에 보내고 투표 수를 가져옵니다.
js/app.js: 버튼 클릭, 카드 그리기, 투표 처리, 설정 저장을 담당합니다.
apps-script/Code.gs: 버스 API 키와 Google Sheets 저장을 대신 처리하는 Apps Script 코드입니다.

확인 체크리스트

  • index.html을 찾았습니다.
  • css/style.css를 찾았습니다.
  • js/config.js를 찾았습니다.
  • apps-script/Code.gs는 Google Apps Script 프로젝트에 붙여넣는 코드라는 점을 압니다.

자주 나는 오류

  • config.js를 고쳤는데 화면이 안 바뀝니다: 저장했는지 확인하고 브라우저를 새로고침합니다.
  • 파일 이름 대소문자가 다릅니다: GitHub Pages에서는 대소문자가 중요합니다.
  • Apps Script 코드를 GitHub Pages에 넣으려고 합니다: Code.gs는 Apps Script에 넣는 코드입니다.

2장. 날씨 API 붙이기

이번 목표

키가 필요 없는 공개 API를 화면에 표시합니다. Open-Meteo는 API 키 없이 사용할 수 있어서 첫 API 실습에 적합합니다.

따라하기

  1. js/config.js를 엽니다.
  2. weather 설정을 찾습니다.
  3. label, latitude, longitude 값을 확인합니다.
  4. 서울 값을 다른 지역 값으로 바꿔 봅니다.
  5. 저장하고 새로고침합니다.

코드 붙여넣기

weather: {
  enabled: true,
  label: "부산",
  latitude: 35.1796,
  longitude: 129.0756
}

확인 체크리스트

  • weather.enabled가 true입니다.
  • label을 바꾸면 화면의 지역 이름이 바뀝니다.
  • 위도와 경도를 바꾸면 날씨 값이 달라질 수 있습니다.
  • 브라우저 Console에 오류가 없습니다.

AI에게 물어볼 프롬프트

아래 config.js의 weather 설정을 제주도로 바꾸고 싶어.
JavaScript 문법이 깨지지 않게 수정 예시를 보여줘.

3장. 급식 오늘/내일 표시하기

이번 목표

NEIS 급식 API에서 오늘과 내일의 중식 메뉴를 가져와 화면에 표시합니다.

따라하기

  1. js/config.js에서 schoolMeal 설정을 찾습니다.
  2. 교육청 코드, 학교 코드, 학교 이름을 확인합니다.
  3. mealCode가 "2"인지 확인합니다. "2"는 중식입니다.
  4. mealDate가 비어 있는지 확인합니다.
  5. 저장하고 새로고침합니다.

코드 붙여넣기

schoolMeal: {
  enabled: true,
  educationOfficeCode: "B10",
  schoolCode: "7010073",
  schoolName: "당곡고등학교",
  mealCode: "2",
  mealDate: ""
}

mealDate가 비어 있으면 한국 시간 기준 오늘과 내일을 자동으로 조회합니다. 특정 날짜부터 보고 싶으면 20260526처럼 넣습니다.

확인 체크리스트

  • 급식 카드가 오늘과 내일로 나뉩니다.
  • mealCode: "2"가 중식이라는 점을 설명할 수 있습니다.
  • mealDate를 비우면 자동 날짜가 사용됩니다.
  • 특정 날짜를 넣으면 그 날짜부터 이틀을 조회합니다.

4장. 급식 투표를 Google Sheets에 저장하기

이번 목표

급식 메뉴 투표가 브라우저 안에만 남지 않고 Google Sheets에 쌓이도록 연결합니다.

핵심 흐름

투표 버튼 클릭
  → js/app.js가 투표 정보를 만듭니다.
  → js/adapters/vote-store.js가 Apps Script Web App URL로 보냅니다.
  → Apps Script가 Google Sheets에 한 줄을 추가합니다.
  → Apps Script가 전체 투표 수를 다시 계산해 돌려줍니다.
  → 화면의 투표 수가 업데이트됩니다.

따라하기

  1. Google Sheets에서 새 스프레드시트를 만듭니다.
  2. 스프레드시트 주소에서 Sheet ID를 복사합니다.
  3. Apps Script 프로젝트 설정에서 Script Properties를 엽니다.
  4. MEAL_VOTE_SHEET_ID에 Sheet ID를 넣습니다.
  5. apps-script/Code.gs를 붙여넣고 새 버전으로 배포합니다.
  6. 샘플 앱에서 급식 메뉴에 투표합니다.
  7. 시트의 meal_votes 탭에 행이 생기는지 확인합니다.

저장되는 열

createdAt
mealDate
mealTitle
menuName
voteKey
userAgent

확인 체크리스트

  • Apps Script에 MEAL_VOTE_SHEET_ID가 있습니다.
  • Apps Script가 새 버전으로 배포되었습니다.
  • Web App URL이 앱에 들어 있습니다.
  • 투표 후 Google Sheets에 행이 추가됩니다.
  • 새로고침 후에도 투표 수가 유지됩니다.

5장. 버스 도착 정보 붙이기

이번 목표

마을버스 도착 정보를 화면에 붙입니다. 버스 API는 키와 CORS 문제가 있어서 브라우저가 직접 호출하지 않고 Apps Script 프록시를 사용합니다.

왜 프록시가 필요한가요

GitHub Pages는 공개 웹사이트입니다. 여기에 버스 API 키를 넣으면 다른 사람이 볼 수 있습니다. 또한 서울 버스 API는 브라우저에서 직접 호출할 때 HTTP/CORS 문제를 만날 수 있습니다.

브라우저 앱
  → Apps Script Web App URL
  → Script Properties의 BUS_API_KEY 읽기
  → 서울 버스 API 호출
  → 필요한 정보만 브라우저에 반환

따라하기

  1. 서울 버스 API 키를 준비합니다.
  2. Apps Script 프로젝트를 엽니다.
  3. Script Properties에 BUS_API_KEY를 추가합니다.
  4. apps-script/Code.gs를 붙여넣습니다.
  5. 새 배포에서 웹 앱을 선택합니다.
  6. 실행 사용자는 나, 액세스 권한은 모든 사용자로 설정합니다.
  7. Web App URL을 복사합니다.
  8. 샘플 앱의 마을버스 프록시 설정에 URL을 넣습니다.
  9. 정류소번호와 노선명을 확인하고 저장하고 조회를 누릅니다.

코드 붙여넣기

villageBus: {
  enabled: true,
  proxyUrl: "https://script.google.com/macros/s/.../exec",
  arsId: "21347",
  routeName: "관악11"
}

자주 나는 오류

  • NO_BUS_API_KEY: Apps Script Script Properties에 BUS_API_KEY가 없습니다.
  • Web App URL 403: 배포 권한이 모든 사용자가 아니거나 첫 실행 권한 승인이 아직 안 되었을 수 있습니다.
  • 버스 설정을 지웠는데도 이상합니다: 브라우저 localStorage에 예전 설정이 남아 있을 수 있습니다.

6장. 나만의 학교/정류소로 바꾸기

이번 목표

샘플 앱을 내 생활권에 맞게 바꿉니다. 이 장에서는 작동하는 앱을 유지하면서 설정값만 바꿉니다.

따라하기

  1. 현재 작동하는 상태를 먼저 확인합니다.
  2. js/config.js를 복사해 백업합니다.
  3. 날씨 지역을 바꿉니다.
  4. 학교 급식 설정을 바꿉니다.
  5. 정류소번호와 노선명을 바꿉니다.
  6. 새로고침해서 각 카드가 따로 작동하는지 확인합니다.
  7. GitHub에 커밋하고 GitHub Pages 주소를 확인합니다.

바꿀 값 정리

날씨: label, latitude, longitude
급식: educationOfficeCode, schoolCode, schoolName, mealCode, mealDate
버스: proxyUrl, arsId, routeName

확인 체크리스트

  • 날씨 지역 이름이 바뀌었습니다.
  • 급식 학교 이름이 바뀌었습니다.
  • 급식 날짜가 오늘과 내일 기준입니다.
  • 버스 정류소번호와 노선명이 바뀌었습니다.
  • 투표가 Google Sheets에 저장됩니다.
  • GitHub Pages 주소에서 앱이 열립니다.

부록. Apps Script와 오류 해결

필요한 Script Properties

BUS_API_KEY: 서울 버스 API 키입니다. GitHub에 올리지 않습니다.
MEAL_VOTE_SHEET_ID: 급식 투표를 저장할 Google Sheets의 스프레드시트 ID입니다.
BUS_ALERT_EMAIL: 교사용 5분 전 메일 알림을 받을 주소입니다. 선택 사항입니다.

배포 설정

배포 유형: 웹 앱
실행 사용자: 나
액세스 권한: 모든 사용자

문제 해결

  • 화면이 안 열릴 때: GitHub Pages 주소, index.html, 배포 완료 여부를 확인합니다.
  • 날씨가 안 나올 때: weather.enabled, 위도/경도, 쉼표를 확인합니다.
  • 급식이 안 나올 때: 교육청 코드, 학교 코드, mealCode, 휴일 여부를 확인합니다.
  • 투표가 저장되지 않을 때: MEAL_VOTE_SHEET_ID, Apps Script 새 배포, Google Sheets 권한을 확인합니다.
  • 버스가 안 나올 때: BUS_API_KEY, /exec URL, 정류소번호, 노선명을 확인합니다.
