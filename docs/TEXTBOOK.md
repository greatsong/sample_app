# 생활 데이터 웹앱 만들기

완성본 체험에서 시작해 GitHub Pages 배포, 바이브코딩 작업법, 공개 데이터 API, Google Sheets 저장, Apps Script 프록시, 자기화와 발표까지 이어지는 프로젝트형 웹교재입니다.

## 00장. 완성본을 먼저 해부하기

코드를 건드리기 전에 생활 데이터 앱이 어떤 문제를 해결하는지 관찰하고, 앞으로 바꿀 방향을 정합니다.

- 산출물: 관찰 기록, 데이터 흐름 스케치, 나의 생활권 앱 기획 한 줄
- 교사용 포인트: 첫 화면에서는 설명을 길게 하지 않습니다. 완성 앱을 열고 실제로 날씨, 급식, 투표, 버스 카드가 움직이는 모습을 먼저 보여줍니다.
- 대표 프롬프트: 생활 데이터 웹앱을 처음 보는 학생에게 날씨, 급식, 투표, 버스 카드가 각각 어떤 역할을 하는지 설명해줘.

## 01장. 내 앱 URL 만들기

GitHub Pages로 각자 수정할 수 있는 웹앱 주소를 만들고, 수정-커밋-배포 루프를 익힙니다.

- 산출물: 내 GitHub Pages URL, 첫 수정 commit, 배포 확인 캡처
- 교사용 포인트: 이 장의 성공 기준은 멋진 수정이 아니라 배포 URL이 열리는 것입니다.
- 대표 프롬프트: GitHub 저장소 주소와 GitHub Pages 주소의 차이를 중학생도 이해할 수 있게 설명해줘.

## 02장. 바이브코딩 작업법 익히기

AI에게 한 번에 완성품을 맡기지 않고, 작은 수정과 검증을 반복하는 웹앱 제작 루틴을 익힙니다.

- 산출물: 파일 역할 지도, 오류 질문 템플릿, 첫 AI 협업 기록
- 교사용 포인트: 이 장은 기능을 많이 추가하는 장이 아니라 작업 습관을 만드는 장입니다.
- 대표 프롬프트: 아래 파일 목록을 보고 생활 데이터 웹앱의 구조를 초보자에게 설명해줘.

## 03장. 공개 데이터 붙이기

키 없이 쓸 수 있는 날씨와 학교 급식 데이터를 연결해 첫 API 성공 경험을 만듭니다.

- 산출물: 내 지역 날씨 카드, 내 학교 급식 카드, API 요청 관찰 기록
- 교사용 포인트: 첫 API는 키가 필요 없는 날씨로 시작해야 실패 지점이 줄어듭니다.
- 대표 프롬프트: Open-Meteo 날씨 설정에서 label, latitude, longitude가 각각 무슨 뜻인지 설명해줘.

## 04장. 사용자 행동 저장하기

급식 투표를 Google Sheets에 저장하면서 브라우저 안 데이터와 공용 저장 데이터의 차이를 배웁니다.

- 산출물: meal_votes 시트, 투표 저장 성공 화면, 저장되는 열 설명
- 교사용 포인트: 이 장부터는 학생이 만드는 데이터가 등장합니다. 공개 API를 읽는 것과 사용자의 행동을 저장하는 것은 완전히 다른 경험입니다.
- 대표 프롬프트: 급식 투표가 Google Sheets에 저장되는 흐름을 버튼 클릭부터 화면 업데이트까지 설명해줘.

## 05장. 비밀키 숨기는 프록시 만들기

버스 API 키를 공개 코드에 넣지 않고 Apps Script 프록시를 통해 안전하게 실시간 도착 정보를 가져옵니다.

- 산출물: 버스 프록시 URL, 내 정류소 도착 카드, 보안 설명 기록
- 교사용 포인트: 이 장은 어렵지만 매우 중요합니다. 학생에게 모든 세부 기술을 외우게 하기보다 '브라우저에 비밀키를 넣으면 안 된다'는 원칙을 분명히 남깁니다.
- 대표 프롬프트: GitHub Pages에서 API 키를 직접 넣으면 왜 위험한지 학교 수업 예시로 설명해줘.

## 06장. 내 생활권 앱으로 리디자인하기

샘플 앱을 우리 학교, 우리 정류소, 우리 반 사용자를 위한 생활 데이터 도구로 바꿉니다.

- 산출물: 내 생활권 앱 URL, 최종 설정표, 개선 전후 캡처
- 교사용 포인트: 이 장에서는 기능을 새로 많이 붙이는 것보다 사용자에게 맞추는 경험을 줍니다.
- 대표 프롬프트: 생활 데이터 앱을 우리 학교 학생이 쓰기 좋게 바꾸려면 카드 순서와 문구를 어떻게 다듬으면 좋을지 제안해줘.

## 07장. 발표와 갤러리

기능 자랑이 아니라 데이터 흐름과 보안 판단을 설명하고, 친구 피드백을 다음 버전 계획으로 바꿉니다.

- 산출물: 1분 발표, 자기평가, 친구 피드백 3개, 다음 버전 이슈 1개
- 교사용 포인트: 발표는 디자인 자랑으로 흐르기 쉽습니다. 반드시 데이터 출처, 저장 위치, 숨긴 키, 다음 개선을 말하게 합니다.
- 대표 프롬프트: 내 생활 데이터 웹앱 발표를 1분짜리로 준비하려고 해. 문제, 데이터 출처, 내가 바꾼 점, 보안상 신경 쓴 점, 다음 버전 계획 순서로 대본을 만들어줘.

## 수업 원칙

- 완성본을 먼저 체험합니다.
- 한 번에 하나만 바꾸고 바로 확인합니다.
- 데이터 출처, 저장 위치, 비밀키 처리 방식을 설명합니다.
- AI 답변은 실행 결과와 오류 기록으로 검증합니다.
