목차이전 장다음 장

Phase 3

공개 데이터 붙이기

오늘부터 앱은 더 이상 정적인 화면이 아닙니다. 외부 데이터가 들어오면서 매일 달라지는 도구가 됩니다.

최종 산출물
내 지역 날씨 카드, 내 학교 급식 카드, API 요청 관찰 기록
교사용 운영 포인트
  • 첫 API는 키가 필요 없는 날씨로 시작해야 실패 지점이 줄어듭니다.
  • 급식 API는 학생 생활과 바로 연결되므로 몰입도가 높지만, 휴일과 방학에는 데이터가 없을 수 있음을 먼저 말합니다.
  • Network 탭은 깊게 가르치지 말고 '요청이 갔는가, 성공했는가, 데이터가 왔는가' 세 가지만 보게 합니다.

날씨 데이터

날씨 카드는 지역 이름, 위도, 경도 설정으로 움직입니다. 지역 이름은 화면에 보이는 라벨이고, 실제 데이터는 위도와 경도 기준으로 가져옵니다.

학생은 지역 이름만 바꾸면 데이터가 바뀐다고 생각하기 쉽습니다. 이 장에서는 라벨과 실제 요청 값의 차이를 강조합니다.

weather: {
  enabled: true,
  label: "서울",
  latitude: 37.5665,
  longitude: 126.9780
}

급식 데이터

급식 카드는 NEIS 급식 API를 사용합니다. 학교 이름만으로는 데이터를 가져올 수 없고, 교육청 코드와 학교 코드가 함께 필요합니다.

mealCode는 조식, 중식, 석식을 구분합니다. 수업에서는 보통 중식 코드만 다룹니다. 날짜를 비워 두면 오늘과 내일을 자동으로 보여주는 방식이 초보자에게 가장 쉽습니다.

schoolMeal: {
  enabled: true,
  educationOfficeCode: "B10",
  schoolCode: "7010073",
  schoolName: "당곡고등학교",
  mealCode: "2",
  mealDate: ""
}

수업 활동

  • 날씨 지역을 하나 바꿔 보고 화면과 Network 탭을 확인합니다.
  • 급식 학교 이름, 교육청 코드, 학교 코드가 함께 움직인다는 점을 확인합니다.
  • 오늘 급식이 비어 있을 때 코드 오류인지 데이터 공백인지 구분합니다.
  • 내 생활권 앱에 필요한 공개 데이터 후보를 하나 더 찾아봅니다.

AI 프롬프트 카탈로그

  • Open-Meteo 날씨 설정에서 label, latitude, longitude가 각각 무슨 뜻인지 설명해줘.
  • NEIS 급식 설정에서 교육청 코드와 학교 코드가 왜 필요한지 알려줘.
  • Network 탭에서 API 요청이 성공했는지 초보자가 확인하는 방법을 알려줘.

확인 체크리스트

  • 지역 이름과 좌표의 차이를 설명할 수 있다.
  • 급식이 없는 날과 코드 오류를 구분하려고 시도할 수 있다.
  • 공개 API는 브라우저에서 직접 호출해도 되는 경우가 있음을 안다.

확장 활동

날씨와 급식 카드 중 하나를 선택해 우리 반 사용자에게 더 친절한 문구로 바꿉니다.

완성본 체험, GitHub Pages, 공공 API, Google Sheets, Apps Script 프록시, 발표까지 이어지는 생활 데이터 웹앱 교재
