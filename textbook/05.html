Chapter 5

5장. 버스 도착 정보 붙이기

버스 API 키를 브라우저에 넣지 않고 Apps Script 프록시로 안전하게 연결합니다.

목차이전 장다음 장

이번 목표

마을버스 도착 정보를 화면에 붙입니다. 버스 API는 키와 CORS 문제가 있으므로 브라우저가 직접 호출하지 않고 Apps Script가 중간 서버처럼 대신 호출합니다.

왜 프록시가 필요한가요?

GitHub Pages는 공개 웹사이트입니다. 여기에 버스 API 키를 넣으면 다른 사람이 볼 수 있습니다. 또한 일부 공공 API는 브라우저에서 직접 호출할 때 CORS 또는 HTTP 문제를 만납니다.

브라우저 앱
  -> Apps Script Web App URL
  -> Script Properties의 BUS_API_KEY 읽기
  -> 서울 버스 API 호출
  -> 필요한 정보만 브라우저에 반환

따라하기

  1. 서울 버스 API 키를 준비합니다.
  2. Apps Script 프로젝트를 엽니다.
  3. Script Properties에 BUS_API_KEY를 추가합니다.
  4. apps-script/Code.gs를 붙여넣습니다.
  5. 새 배포에서 웹 앱을 선택합니다.
  6. 실행 사용자는 나, 액세스 권한은 모든 사용자로 설정합니다.
  7. Web App URL을 복사합니다.
  8. 샘플 앱의 마을버스 프록시 설정에 URL을 넣습니다.
  9. 정류소번호와 노선명을 입력하고 조회합니다.

설정 예시

villageBus: {
  enabled: true,
  proxyUrl: "https://script.google.com/macros/s/.../exec",
  arsId: "21347",
  routeName: "관악11"
}

체크리스트

  • BUS_API_KEY가 Apps Script Script Properties에 있습니다.
  • Web App URL이 /exec로 끝납니다.
  • 정류소번호와 노선명이 실제 값과 같습니다.
  • 버스 카드가 실시간 연결 상태입니다.

자주 나는 오류

  • 서울 버스 API는 Google API가 아닙니다. api.bus.go.kr에서 확인합니다.
  • NO_BUS_API_KEY는 Script Properties에 BUS_API_KEY가 없다는 뜻입니다.
  • 403 오류는 배포 권한 또는 첫 실행 권한 승인 문제일 수 있습니다.
  • 예전 설정이 남아 있으면 설정 삭제 후 새로고침합니다.

AI 프롬프트

GitHub Pages에서 버스 API 키를 직접 넣지 않고 Apps Script 프록시를 사용하는 이유를
초보자에게 설명해줘. CORS, HTTP, 비밀키 노출 문제를 쉬운 말로 풀어줘.
