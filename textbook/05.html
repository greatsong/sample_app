Phase 5

비밀키 숨기는 프록시 만들기

진짜 웹앱은 데이터를 가져오는 것만큼, 보여주면 안 되는 것을 숨기는 능력이 중요합니다.

최종 산출물
버스 프록시 URL, 내 정류소 도착 카드, 보안 설명 기록
교사용 운영 포인트
  • 이 장은 어렵지만 매우 중요합니다. 학생에게 모든 세부 기술을 외우게 하기보다 '브라우저에 비밀키를 넣으면 안 된다'는 원칙을 분명히 남깁니다.
  • CORS, HTTP/HTTPS, API 키 노출을 한꺼번에 설명하면 어렵습니다. '브라우저가 직접 못 부르는 API를 Apps Script가 대신 부른다'는 그림으로 시작합니다.
  • 실습 시간이 부족하면 교사용 프록시 URL을 제공하고, 학생은 구조 설명과 설정 변경에 집중하게 합니다.

프록시 구조

브라우저 앱
-> Apps Script Web App URL
-> Script Properties에서 BUS_API_KEY 읽기
-> 서울 버스 API 호출
-> 필요한 도착 정보만 브라우저에 반환

왜 직접 호출하지 않는가

GitHub Pages에 올라간 JavaScript 파일은 누구나 볼 수 있습니다. 여기에 API 키를 적으면 사실상 전교생뿐 아니라 인터넷 전체에 키를 공개하는 셈입니다.

또 어떤 공공 API는 브라우저에서 직접 호출할 때 CORS나 HTTP/HTTPS 문제를 만납니다. Apps Script는 브라우저 대신 API를 호출하고, 브라우저에는 필요한 결과만 돌려주는 중간 서버 역할을 합니다.

따라하기

  • 서울 버스 API 키를 준비합니다.
  • Apps Script Script Properties에 BUS_API_KEY를 넣습니다.
  • Code.gs를 붙여넣고 웹 앱으로 새 배포를 만듭니다.
  • 실행 사용자는 나, 액세스 권한은 모든 사용자로 둡니다.
  • Web App URL이 /exec로 끝나는지 확인합니다.
  • 앱 설정에 proxyUrl, arsId, routeName을 넣고 조회합니다.

보안 설명 문장

이 앱은 버스 API 키를 GitHub Pages 코드에 넣지 않습니다. 키는 Apps Script의 Script Properties에 보관하고, 브라우저는 Apps Script 주소만 호출합니다. 그래서 사용자는 도착 정보를 볼 수 있지만 실제 키는 볼 수 없습니다.

AI 프롬프트 카탈로그

  • GitHub Pages에서 API 키를 직접 넣으면 왜 위험한지 학교 수업 예시로 설명해줘.
  • Apps Script 프록시 구조를 브라우저, 프록시, 공공 API 세 단계로 설명해줘.
  • CORS와 HTTPS 문제를 초보자에게 비유로 설명해줘.

확인 체크리스트

  • BUS_API_KEY가 GitHub 파일 안에 없다.
  • proxyUrl은 /exec로 끝난다.
  • 버스 카드가 실시간 연결 상태다.
  • 프록시가 하는 일을 한 문단으로 설명할 수 있다.

확장 활동
