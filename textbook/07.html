목차 이전 장 마무리

Phase 7

발표와 갤러리

진짜 프로젝트는 만든 뒤 끝나지 않습니다. 누군가 써 보고, 질문하고, 다음 버전이 생길 때 프로젝트가 살아납니다.

최종 산출물
1분 발표, 자기평가, 친구 피드백 3개, 다음 버전 이슈 1개
교사용 운영 포인트
  • 발표는 디자인 자랑으로 흐르기 쉽습니다. 반드시 데이터 출처, 저장 위치, 숨긴 키, 다음 개선을 말하게 합니다.
  • 갤러리 워크는 별점보다 구체 피드백 중심으로 운영합니다.
  • climate-action-365처럼 운영 가능한 프로젝트로 이어지려면 마지막에 인계 가능한 기록이 남아야 합니다.

1분 발표 구조

1. 내 앱은 누구에게 필요한가
2. 날씨 데이터는 어디에서 오는가
3. 급식 데이터는 어디에서 오는가
4. 투표 데이터는 어디에 저장되는가
5. 버스 API 키는 어디에 숨겼는가
6. 내가 직접 바꾼 점은 무엇인가
7. 다음 버전에서 고칠 점은 무엇인가

갤러리 피드백

  • 이 앱에서 실제로 바로 쓸 만한 기능은 무엇인가요?
  • 데이터가 어디서 오는지 설명이 이해되었나요?
  • 비밀키를 보호한 구조가 납득되었나요?
  • 모바일에서 읽기 쉬웠나요?
  • 다음 버전에 추가하면 좋을 생활 데이터는 무엇인가요?

AI 프롬프트 카탈로그

  • 내 생활 데이터 웹앱 발표를 1분짜리로 준비하려고 해. 문제, 데이터 출처, 내가 바꾼 점, 보안상 신경 쓴 점, 다음 버전 계획 순서로 대본을 만들어줘.
  • 친구 피드백을 다음 버전 개발 이슈로 바꾸는 문장 예시를 만들어줘.
  • 내 앱의 데이터 흐름을 발표용으로 짧게 설명해줘.

확인 체크리스트

  • 내 앱 URL이 열린다.
  • 데이터 출처를 설명할 수 있다.
  • API 키를 어디에 숨겼는지 설명할 수 있다.
  • 친구 피드백 3개를 다음 계획으로 바꿨다.

확장 활동

우수작을 학급 갤러리 페이지로 모으고, 다음 학기 학생들이 fork해서 이어 만들 수 있게 합니다.
