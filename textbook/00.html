목차다음 장

Phase 0

완성본을 먼저 해부하기

오늘은 코딩을 시작하지 않습니다. 대신 이미 완성된 앱을 사용자처럼 써 보고, 개발자처럼 질문을 뽑습니다.

최종 산출물
관찰 기록, 데이터 흐름 스케치, 나의 생활권 앱 기획 한 줄
교사용 운영 포인트
  • 첫 화면에서는 설명을 길게 하지 않습니다. 완성 앱을 열고 실제로 날씨, 급식, 투표, 버스 카드가 움직이는 모습을 먼저 보여줍니다.
  • 학생에게 '이 앱은 코드 예제가 아니라 내 생활을 확인하는 도구'라는 감각을 주는 것이 이 장의 핵심입니다.
  • 기능 이름을 외우게 하지 말고, 카드마다 '데이터가 어디서 오고 누가 쓰는가'를 말하게 합니다.

이 장의 질문

웹앱은 단순히 예쁜 화면이 아니라, 필요한 데이터를 가져와 사람이 판단하기 쉽게 보여주는 도구입니다. 이 장에서는 완성본을 사용자 관점과 개발자 관점으로 나누어 봅니다.

사용자 관점의 질문은 '오늘 점심은 무엇인가', '지금 버스는 몇 분 뒤에 오는가', '우리 반은 어떤 메뉴를 더 좋아하는가'입니다. 개발자 관점의 질문은 '이 데이터는 어디서 왔는가', '새로고침해도 남는 데이터는 무엇인가', '숨겨야 하는 값은 무엇인가'입니다.

학생 활동

  • 완성 앱을 열고 날씨, 급식, 투표, 버스 영역을 색연필 네 가지로 표시합니다.
  • 각 카드에 대해 데이터 출처, 사용자 행동, 저장 여부를 적습니다.
  • 급식 투표를 한 번 누르고, 새로고침 후 숫자가 어떻게 되는지 관찰합니다.
  • 버스 카드가 실시간 연결인지, 설정이 필요한 상태인지 문장으로 기록합니다.
  • 내 학교 생활에 더 붙이고 싶은 데이터 한 가지를 제안합니다.

개념 정리

날씨와 급식은 공개 데이터 API에서 옵니다. 투표는 사용자가 직접 만든 데이터입니다. 버스는 비밀키가 필요한 API라서 브라우저가 직접 부르지 않고 중간 서버 역할을 하는 Apps Script를 거칩니다.

이 구분이 이후 모든 장의 기준입니다. 공개 데이터, 사용자 입력 데이터, 비밀키가 필요한 데이터는 다루는 방식이 다릅니다.

AI 프롬프트 카탈로그

  • 생활 데이터 웹앱을 처음 보는 학생에게 날씨, 급식, 투표, 버스 카드가 각각 어떤 역할을 하는지 설명해줘.
  • 이 앱에서 공개 데이터와 사용자 입력 데이터와 비밀키가 필요한 데이터를 구분해줘.
  • 내가 관찰한 내용을 바탕으로 생활 데이터 앱 기획 한 줄을 만들어줘.

확인 체크리스트

  • 네 개 카드의 역할을 구분할 수 있다.
  • 데이터가 화면에 보이기까지 어딘가에서 가져오거나 저장된다는 점을 설명할 수 있다.
  • 비밀키가 공개 웹페이지에 들어가면 안 된다는 문제를 말할 수 있다.

확장 활동

학생이 제안한 생활 데이터 후보를 칠판에 모으고, 공개 API로 가능한 것과 직접 저장해야 하는 것을 분류합니다.

완성본 체험, GitHub Pages, 공공 API, Google Sheets, Apps Script 프록시, 발표까지 이어지는 생활 데이터 웹앱 교재
