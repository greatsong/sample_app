01장. 내 앱 URL 만들기

GitHub Pages로 각자 수정할 수 있는 웹앱 주소를 만들고, 수정-커밋-배포 루프를 익힙니다.

목차이전 장다음 장

Phase 1

내 앱 URL 만들기

저장소 주소는 작업장이고, Pages 주소는 손님에게 보여주는 가게입니다. 오늘은 내 가게 주소를 만듭니다.

최종 산출물
내 GitHub Pages URL, 첫 수정 commit, 배포 확인 캡처
교사용 운영 포인트
  • 이 장의 성공 기준은 멋진 수정이 아니라 배포 URL이 열리는 것입니다.
  • GitHub UI가 바뀌어도 학생이 길을 잃지 않도록 저장소 생성, 파일 수정, commit, Pages 확인의 네 동작만 반복해서 말합니다.
  • 배포 대기 시간이 있다는 점을 먼저 알려주면 404를 실패로 받아들이지 않습니다.

수업 흐름

  • 교사가 데모 저장소의 Pages URL을 먼저 보여줍니다.
  • 학생은 샘플 앱을 자기 저장소로 가져옵니다.
  • README가 아니라 실제 화면 파일을 아주 작게 수정합니다.
  • commit 후 GitHub Pages 주소를 확인합니다.
  • 친구 스마트폰에서 내 URL이 열리는지 확인합니다.

핵심 설명

GitHub 저장소는 파일을 보관하고 수정 이력을 남기는 작업 공간입니다. GitHub Pages는 그 파일 중 웹사이트로 보여줄 수 있는 파일을 인터넷 주소로 공개합니다.

학생이 가장 많이 헷갈리는 것은 저장소 URL과 웹사이트 URL입니다. 저장소 URL에는 코드가 보이고, Pages URL에는 결과 화면이 보입니다.

따라하기

  • 샘플 저장소를 내 계정으로 복사합니다.
  • Settings 또는 Actions에서 Pages 배포 상태를 확인합니다.
  • index.html에서 화면 문구 하나만 바꿉니다.
  • commit 메시지는 '첫 문구 수정'처럼 사람이 읽을 수 있게 씁니다.
  • 1~2분 뒤 Pages URL을 새로고침합니다.
  • 배포가 되면 URL을 제출합니다.

오류 진단

404가 떠도 대부분 실패가 아닙니다. 배포가 아직 끝나지 않았거나, 파일 이름이 다르거나, Pages 설정이 다른 브랜치를 보고 있을 가능성이 큽니다.

수정했는데 화면이 그대로라면 캐시, 배포 대기, 다른 파일 수정 중 하나입니다. 학생에게 한 번에 한 가지 원인만 확인하게 합니다.

AI 프롬프트 카탈로그

  • GitHub 저장소 주소와 GitHub Pages 주소의 차이를 중학생도 이해할 수 있게 설명해줘.
  • GitHub Pages에서 404가 나올 때 확인할 것을 순서대로 알려줘.
  • 내가 쓴 commit 메시지를 더 알아보기 쉽게 고쳐줘.

확인 체크리스트

  • 내 Pages URL을 친구 기기에서 열 수 있다.
  • 저장소 URL과 웹사이트 URL을 구분할 수 있다.
  • commit 후 배포 반영까지 시간이 걸릴 수 있음을 안다.

확장 활동

Pages 주소를 QR 코드로 만들어 교실 게시판에 붙이면 이후 장에서 서로 빠르게 접속할 수 있습니다.
