04장. 사용자 행동 저장하기

급식 투표를 Google Sheets에 저장하면서 브라우저 안 데이터와 공용 저장 데이터의 차이를 배웁니다.

목차이전 장다음 장

Phase 4

사용자 행동 저장하기

화면에서 버튼을 누르는 순간, 그 행동은 데이터가 됩니다. 오늘은 그 데이터를 잃어버리지 않게 저장합니다.

최종 산출물
meal_votes 시트, 투표 저장 성공 화면, 저장되는 열 설명
교사용 운영 포인트
  • 이 장부터는 학생이 만드는 데이터가 등장합니다. 공개 API를 읽는 것과 사용자의 행동을 저장하는 것은 완전히 다른 경험입니다.
  • Google Sheets를 데이터베이스처럼 쓰는 것은 정식 운영의 끝판왕은 아니지만, 초보자에게 저장의 개념을 보여주기에 매우 좋습니다.
  • 권한 승인과 새 배포 때문에 막히는 학생이 많으므로 교사용 데모 Apps Script를 먼저 보여주고 시작합니다.

데이터 흐름

투표 버튼 클릭
-> app.js가 메뉴와 날짜 정보를 묶음
-> vote-store.js가 Apps Script Web App URL로 전송
-> Apps Script가 Google Sheets에 한 줄 추가
-> Apps Script가 메뉴별 투표 수 계산
-> 브라우저가 최신 투표 수로 화면 업데이트

왜 날짜가 필요한가

급식 메뉴는 반복됩니다. 오늘의 김치와 내일의 김치를 같은 항목으로 합치면 데이터가 망가집니다. 그래서 voteKey는 메뉴 이름만이 아니라 날짜와 메뉴를 함께 묶어야 합니다.

이 설명은 데이터베이스의 기본 개념으로 이어집니다. 데이터를 저장할 때는 사람이 보기 좋은 이름만으로 충분하지 않고, 구분 가능한 키가 필요합니다.

따라하기

  • Google Sheets에서 새 스프레드시트를 만듭니다.
  • 주소에서 Sheet ID를 복사합니다.
  • Apps Script Script Properties에 MEAL_VOTE_SHEET_ID를 넣습니다.
  • apps-script/Code.gs를 붙여넣고 웹 앱으로 배포합니다.
  • 샘플 앱에서 투표하고 meal_votes 탭에 행이 생기는지 확인합니다.
  • 새로고침 후에도 투표 수가 유지되는지 봅니다.

저장되는 열

createdAt    투표가 저장된 시각
mealDate     급식 날짜
mealTitle    오늘 중식 또는 내일 중식
menuName     투표한 메뉴 이름
voteKey      날짜와 메뉴를 합친 식별자
userAgent    어떤 브라우저에서 보냈는지 참고 정보

AI 프롬프트 카탈로그

  • 급식 투표가 Google Sheets에 저장되는 흐름을 버튼 클릭부터 화면 업데이트까지 설명해줘.
  • voteKey가 왜 필요한지 오늘의 김치와 내일의 김치 예시로 설명해줘.
  • Google Sheets를 간단한 데이터베이스처럼 사용할 때 장점과 한계를 알려줘.

확인 체크리스트

  • 투표 후 시트에 행이 추가된다.
  • 새로고침 후에도 투표 수가 유지된다.
  • voteKey의 필요성을 설명할 수 있다.
  • Apps Script를 새로 배포해야 변경이 반영된다는 점을 안다.

확장 활동

투표 결과를 그래프로 보여주는 아이디어를 AI에게 물어보고, 실제 구현 전 필요한 데이터 구조를 먼저 적어 봅니다.

완성본 체험, GitHub Pages, 공공 API, Google Sheets, Apps Script 프록시, 발표까지 이어지는 생활 데이터 웹앱 교재
